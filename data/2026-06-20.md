### 15:40 @unknown

Single Agent vs. Multi-Agent Architecture  Some tasks need a single agent. Others need a whole team. Knowing the difference is the skill.  Single-agent system: One reasoning LLM that plans, picks a tool, and loops on its own until the task is done. Use a single agent when: - the task is a clear, linear sequence - one agent can hold the whole problem in its head - you want something simple to build and easy to debug  Multi-agent system: An orchestrator that splits a task into subtasks and routes each one to a specialized agent. Use multi-agent when: - subtasks can run in parallel - one agent writes and another independently verifies the work - the problem is too big for one agent to coordinate alone  Single agents are cheaper and easier to build, but they hit a ceiling on complex work.   Multi-agent systems are more capable and more reliable, but they add coordination cost.  Start with a single agent. Move to multi-agent only when context or reliability become the bottleneck. They call it Retrieval Collapse.  Here is the mechanism.  Every AI search engine and every RAG system, ChatGPT search, Perplexity, Google's AI overviews, and the retrieval layer behind countless enterprise AI tools works the same way. It pulls documents from the web. It reads them. It generates an answer grounded in what it retrieved.  That design assumes the web is mostly written by humans.  The web is no longer mostly written by humans. AI-generated content already makes up a large and rising share of everything published online. And AI search systems are increasingly retrieving evidence that was itself generated by AI, creating a self-referential cycle the researchers describe as an ecosystem-level structural risk.  So they ran a controlled experiment to measure exactly when it breaks.  They built a test environment using the MS MARCO dataset 1,000 real questions paired with human-validated reference answers. For each question they retrieved 10 real web documents, building a pool of 10,000. Then they gradually replaced human content with AI-generated content and watched what happened to the answers.  Here is what they found in the first scenario, high-quality SEO-style AI content.  A 67% pool contamination led to over 80% exposure contamination.  When 67% of the available documents were AI-generated, more than 80% of the documents the system actually retrieved and showed to users were synthetic. The contamination amplifies. The AI-generated content is optimized for exactly the signals that ranking systems reward, so it dominates the top results far beyond its actual share of the pool.  And here is the part that makes it a trap rather than just a problem.  Answer accuracy remained stable. It went from roughly 68% to 70%. It actually improved slightly.  Because the SEO content was high-quality and topically aligned, the system looked perfectly healthy when measured by accuracy alone. The answers were still correct. The user saw no degradation. Nothing on any dashboard would have flagged a problem.  But nearly all the retrieved evidence was now synthetic. The diversity of sources collapsed. The system was answering questions using an echo chamber of AI-generated content that all traced back to the same underlying models and it had no idea.  The researchers call this a deceptively healthy state. Surface-level quality stays stable. The underlying erosion of information provenance is completely masked. Stage one: high-quality AI content quietly dominates results and erodes source diversity while accuracy stays stable and everything looks fine.
