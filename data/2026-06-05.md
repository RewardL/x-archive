## 关键词 "LLM"

### 15:40 @unknown

How does vLLM serve LLMs efficiently? Let's understand.  Serving an LLM in production is hard. Many users send prompts at the same time, each generation is long, and the KV cache eats GPU memory fast.  A naive server gives every request a large, fixed block of GPU memory for the KV cache. Most of that block stays empty because we do not know how long the output will be. Hence, a lot of GPU memory is wasted, and we cannot fit many requests in parallel.  So, here comes vLLM to the rescue.  vLLM is an open-source library that serves LLMs with very high throughput. Its main idea is called PagedAttention.  PagedAttention is inspired by virtual memory in operating systems. Instead of giving each request one big chunk of GPU memory, vLLM breaks the KV cache into small fixed-size blocks called pages. Each request gets only as many pages as it actually needs.  Let's say a user is generating a long answer. vLLM keeps adding new pages to that request as more tokens come in. When the request finishes, those pages are freed and reused by other requests.  This way, the GPU memory is packed tightly. Fragmentation is almost zero. More requests fit on the same GPU.  vLLM also uses something called continuous batching. The server does not wait for the whole batch to finish. As soon as one request completes, a new one slides into its place. The GPU is always busy.  The result: 2x to 24x higher throughput than a naive server on the same hardware.  In simple words, vLLM treats GPU memory like an operating system treats RAM. Smart paging, smart batching, no waste.  This is how vLLM serves LLMs efficiently.
